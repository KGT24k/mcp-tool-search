How it works

Three steps. No config rewrite. Your existing MCP servers keep working exactly as before.

1

Build a catalog

Run mcp-build-catalog once — it scans your MCP config, connects to each server, snapshots every tool schema into a single JSON file, then disconnects.

2

Swap your config

Replace your MCP server entries with a single mcp-tool-search entry. Your backend servers are now loaded lazily on demand.

3

Let the AI search

Instead of loading 200+ tool schemas upfront, Claude searches for tools by name, gets schemas on demand, and calls them through the proxy.

Built for production

Lightweight, secure, and compatible with every MCP client.

⚡

Lazy Connection Pooling

Backend servers are spawned on first call and kept alive for 5 minutes. LRU eviction when at capacity. Zero cold-start waste.

🔍

Fuzzy Search

Token-based scoring with prefix matching, substring matching, and Levenshtein distance. LRU-cached results with 1-minute TTL.

🔒

Env Var Allowlist

Only 16 safe environment variables (PATH, HOME, etc.) are passed to spawned servers. Your API keys never leak to child processes.

🌐

Dual Transport

Stdio for local use, Streamable HTTP for remote clients. DNS rebinding protection, gzip compression, session management built in.

🔄

Auto-Retry with Backoff

Exponential backoff with jitter on EPIPE, ECONNRESET, and spawn errors. Up to 3 retries, capped at 8 seconds.

📦

2 Runtime Dependencies

Just @modelcontextprotocol/sdk and zod. No bloated dependency trees. Passes npm audit with zero vulnerabilities.
